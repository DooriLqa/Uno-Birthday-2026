# Полёт над лагуной: отрисовка и настройка

## Геометрия автомата

`model/layout.ts` — единственное место настройки изображения и игрового экрана.
`artwork` задаёт размеры исходника (1672 × 941), а `screen.x/y/width/height`
задают прямоугольник игры в пикселях этого исходника, от верхнего левого угла.
`screen.radius` — радиус скругления в тех же единицах.
Например, увеличение `screen.x` на 10 сдвинет поле вправо на 10 пикселей
исходного изображения при любом размере окна. Все параметры также можно
передать компоненту через необязательный prop `layout`.

Картинка и прямоугольник игры находятся в одном контейнере с фиксированными
пропорциями. Он заполняет окно по принципу cover, но на узких экранах масштаб
ограничен `maxScreenViewportWidth` (0.94), а по высоте —
`maxScreenViewportHeight` (0.9), чтобы поле не обрезалось даже на сверхшироких
экранах. Ограничения учитывают смещение поля относительно центра картинки.
При таком ограничении по краям может оставаться тёмное пространство.
Не задавайте отдельно для поля значения в vw/vh и независимый object-fit.

Логический мир остаётся 720 × 440. ResizeObserver равномерно масштабирует
всё его содержимое по меньшему из коэффициентов ширины и высоты, центрируя
в стекле. При других пропорциях screen появляются внутренние поля;
персонаж и физика не растягиваются. Фон, счётчик, сообщения и игровые объекты
теперь находятся внутри общего `.flappy-bird-game__display`.

Раньше фон автомата масштабировался независимо через cover, поле задавалось
через vw/vh, а пропорции stage были 720/484 при мире 720/440. Это приводило
к смещению и несовпадающему масштабированию счётчика и объектов.

## CRT: результат исследования (11 сентября 2026)

Фильтр должен охватывать экран автомата целиком: фон, объекты, счётчик и
сообщения. Корпус, окружение, инвентарь и курсор остаются снаружи.
CRT включён на общем слое. Текущие параметры находятся в `model/layout.ts`:
`enabled` полностью отключает эффект, остальные значения управляют искажением,
сеткой, виньеткой, контрастом и насыщенностью.

### Подход для текущей HTML-отрисовки

Рекомендация: SVG filter на `.flappy-bird-game__display`, использующий
`feDisplacementMap` с детерминированной картой радиального смещения.
Она смещает пиксели входного изображения по каналам другой картинки.
Применение к общему слою даст одинаковое искажение всем дочерним объектам.
Источник: [MDN — feDisplacementMap](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDisplacementMap).

Поверх сцены, внутри того же слоя, можно добавить неподвижные CSS
repeating-linear-gradient: горизонтальные scanlines и вертикальную RGB-маску.
Это имитация сетки люминофора, а не уменьшение разрешения. Для настоящей
пикселизации нужен отдельный шаг дискретизации. Одна CSS-сетка сама по себе
не искривляет изображение; border-radius только обрезает углы.

Стартовые значения для прототипа: радиальное смещение до 2–4 логических
пикселей у края, шаг сетки 3 пикселя, непрозрачность 0.06–0.10, лёгкая
виньетка, без мерцания. Эти значения — предложение, не измеренный результат.
Сетку разместить с pointer-events:none. Исходный игровой button оставить
снаружи фильтра: управление прыжком не зависит от точных координат клика.

Проверить Chromium, Firefox, Safari; SVG-фильтр может потребовать отдельного
композитинга и повлиять на частоту кадров. Не пересоздавать карту смещения
каждый кадр. При отключённом искажении сохранить обычную графику. При
добавлении точного наведения мышью понадобится обратное преобразование
координат; небольшое визуальное смещение также не должно скрывать столкновения.

### Вариант с PixiJS

PixiJS применяет фильтры к Container вместе с его дочерними объектами;
это подходит для единой обработки игрового экрана. Однако эта мини-игра
сейчас использует DOM-элементы, а не Pixi-сцену: наличие pixi.js в проекте
не позволяет напрямую наложить его фильтр на HTML. Понадобится перенос
отрисовки в canvas, включая текст и счётчик.
Источник: [PixiJS v8 — Filters](https://pixijs.com/8.x/guides/components/filters).

Готовый CRTFilter из pixi-filters предлагает линии развёртки, шум и виньетку.
Его curvature документирован как изгиб линий развёртки. Для изгиба всей
картинки и RGB-сетки следует отдельно проверить шейдер и при необходимости
добавить displacement/custom filter. Зависимость pixi-filters сейчас не
установлена. Источник: [CRTFilter API](https://pixijs.io/filters/docs/CRTFilter.html).

Для текущей задачи начать с DOM + SVG/CSS; переход на PixiJS оправдан, если
нужны дополнительные эффекты или профилирование покажет проблемы с DOM.
